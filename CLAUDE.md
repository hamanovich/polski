# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Справочник польской грамматики на русском. Статический сайт на GitHub Pages (`polski.hamanovich.com`), собирается из данных в предгенерированные HTML-страницы. Обзор для людей - в `README.md`.

## Команды

```sh
npm install          # linkedom - единственная зависимость, нужна только для сборки
npm run build        # все HTML-страницы, 404.html, search-index.js, sitemap.xml, fulltext.txt, content-manifest.json
npm run og           # перерисовывает og/*.png и og/manifest.json (нужен Chrome, запускается вручную)
npm run lint         # scripts/lint-content.mjs: запрещённые символы в исходниках и в выводе
npm run check        # node --check по всем скриптам + lint + scripts/check-build.mjs
npm run drift        # git diff по сгенерированным файлам
npm run verify       # build + check + drift, то же гоняет CI
npm run serve        # статика на localhost:8765
```

**Всегда `npm run build && npm run check` после правки `data.js`, `app.js`, `client.js`, `index.template.html` или `style.css`.** Иначе закоммиченный HTML и хеши ассетов разъедутся с исходниками.

Тестов нет: их роль играет `scripts/check-build.mjs` - `assert`'ы по собранному HTML, запускается только целиком. Многие проверки - зашитые числа и цитаты контента (число упражнений, вариантов падежей, размер колод тренажёра). При правке контента их обновляют вместе с данными: это намеренный «замок» на объём, а не поломка.

`npm run verify` дополнительно требует пустой `git diff` по сгенерированным файлам: падает, если исходники правили без пересборки или пересобранное не добавили в индекс. `plan-40/index.html` исключён: он написан руками.

Git-хуки лежат в `.githooks/`, их включает `npm install` (скрипт `prepare` ставит `core.hooksPath`). `pre-commit` - `node --check` по `data.js` и `app.js`; `pre-push` - `npm run verify` (обойти: `SKIP_VERIFY=1 git push`).

## Архитектура: сборка и рантайм - разные миры

**`data.js` и `app.js` в браузер не попадают.** `scripts/build.mjs` поднимает DOM через linkedom, выполняет оба файла в `node:vm`-песочнице (заглушки только `matchMedia` и `localStorage`), даёт им отрисовать контент в `index.template.html` и вырезает их `<script>`-теги. В браузере остаётся только `client.js`.

- `app.js` - только шаблоны контента и то, что при сборке пишет в разметку (`linkHeadings`, `renderIndex`, `applyTheme`). **Поведение живого сайта правится в `client.js`.**
- Обработчики событий в `app.js` не пишут: при сборке они не сработают, а в браузер файл не уезжает.
- Общий хелпер в обоих файлах - `norm` (и `slug` поверх него). Меняя один, проверь парный.
- Реальные размеры, `IntersectionObserver`, анимации при сборке молча не работают - контент от них зависеть не должен.

### Как build.mjs делает страницы

1. Рендерит один «мастер»-DOM со всеми секциями.
2. Пишет `fulltext.txt` и `search-index.js` (без `.practice`; найденным узлам ставит `id="r-N"`).
3. Для каждой страницы из `scripts/pages.mjs` клонирует мастер, удаляет чужие `.sec`, подставляет title/description/canonical/og/JSON-LD, пейджер и переписывает `data-s`-ссылки в относительные пути. Префикс считается как `"../".repeat(глубина)`: есть вложенные адреса `/gry/*/`.
4. Ссылки вида `#s-verbs/czasy/~slug` переписываются `modernHash()` в новые адреса; `check-build` требует, чтобы ни одной `a[href^="#s-"]` не осталось. Так и пишут внутренние ссылки в шаблонах.
5. `style.css`, `client.js`, `search-index.js` получают `?v=<sha256:10>` от содержимого.

`h1` берётся из поля `h1` в `pages.mjs`: на обычных страницах заменяет первый `h2`, на `cases` и `verbs` добавляется в начало секции (там первый `h2` лежит в варианте).

Если в разделе `TOC_MIN` (5) и больше `h3` вне вариантов, сборка вставляет `nav.toc` после вводного абзаца. Порог продублирован в `check-build.mjs`. На `cases` и `verbs` оглавления нет: роль играют чипы.

### Даты страниц: content-manifest.json

`dateModified` в JSON-LD и `lastmod` в sitemap - своя дата у каждой страницы, из `content-manifest.json` (`ключ: {hash, date}`). `hash` - sha256 готового HTML с вымаранными `?v=` и датой. Совпал - дата из манифеста, разошёлся - сегодняшняя, манифест перезаписывается. Поэтому смена `style.css`/`client.js` дат не двигает, а git для дат не используется. Для `plan-40` хешируется сам файл.

### Варианты вместо вкладок

Падежи и подразделы глаголов отрисовываются все сразу в `.case-variant` / `.verb-variant` внутри `.variant-host`; `client.js` переключает класс `.on`. Без JS CSS показывает их подряд. `check-build.mjs` проверяет селекторы `.sec{display:block}`, `.js .sec{display:none}`, `.content-variant{display:block}`, `html:not(.js) .navpop{display:block}` - переименовывать их только вместе с проверкой.

### Упражнения

Блоки `.practice` исключены из `fulltext.txt` и поиска. Ответы пользователя - в `localStorage`, ключ `polski-exercises-v1`. Проверка ответа сравнивает строку в нижнем регистре, но со знаками препинания: для ответов длиннее слова лучше формат `passage` с пропусками.

## Новый раздел - правка в пяти местах

| Где | Что |
|---|---|
| `data.js` | данные; запись в `TABS` и `GROUPS` (порядок чтения, навигация, пейджер) |
| `app.js` | `render*()` + вызов в блоке «СТАРТ» внизу файла |
| `index.template.html` | пустая `<section id="s-…" class="sec">` |
| `scripts/pages.mjs` | `path`, `h1`, `title`, `description` |
| `scripts/check-build.mjs` | запись в `routes` |

Потом `npm run og` для картинки новой страницы.

## OG-картинки

`npm run og` рисует `og/*.png` через headless Chrome, в `build` не входит. Разметка карточки - `scripts/og-card.mjs`; `og/manifest.json` хранит отпечатки, и изменение `h1` или шаблона роняет `npm run check` с подсказкой `rerun npm run og`.

## Игры

Маршруты `/gry/` и `/gry/<игра>/`. Правила, схемы банков и контракты - в `_games/*.md`, аудиты - в `_audit/*-LINGUIST-AUDIT.md`. Читай соответствующий файл до правки игры.

- Движок и данные подключаются только на странице с `[data-game]`, по таблице `gameAssets` в `build.mjs`. Движки обёрнуты в IIFE и **не объявляют глобальных имён**: они делят область с `client.js`. Заперто в `check-build.mjs`.
- `game-data.js` (Milionerzy, Детектив, Собери фразу) **написан руками**, генератора у него нет намеренно; `scripts/game-candidates.mjs` только печатает заготовки. Таблицу `rules` делят все три банка.
- `trainer-data.js` и `sekunda-data.js` **генерируются** из `data.js`: руками правится только `data.js`.
- Числа для движков (лестница `LADDER`, время `SPEED_CLOCK`) живут в `data.js` и доходят до движка через разметку. В `game.js` их не дублировать.
- Ошибки из игр попадают в очередь повторения тренажёра (`missed` в `polski-trainer-v2`).
- Размеры банков и колод зашиты в `check-build.mjs`.

## Генерируемые файлы - коммитятся, руками не правятся

`index.html`, `*/index.html`, `404.html`, `search-index.js`, `sitemap.xml`, `fulltext.txt`, `content-manifest.json`, `trainer-data.js`, `sekunda-data.js`; отдельно `og/*` через `npm run og`. Они в репозитории, потому что GitHub Pages раздаёт их без Node.js.

Исключение: **`plan-40/index.html` написан руками** и сборкой не переписывается. В sitemap попадает через `extraPages` в `pages.mjs`; его `canonical`, `og:*` и JSON-LD правятся вручную и заперты `assert`'ами в конце `check-build.mjs`.

## Что отдаётся наружу: _config.yml

Pages собирает сайт через Jekyll, поэтому по умолчанию публикуется весь репозиторий. Список `exclude` в `_config.yml` закрывает исходники и служебные файлы (`data.js`, `app.js`, `scripts/`, корневые `.md`, `fulltext.txt`, `content-manifest.json`, ...). Пути с `.` и `_` в начале Jekyll не публикует сам. **`.nojekyll` ставить нельзя**: он выключит `exclude`.

`check-build.mjs` требует, чтобы любой файл в корне был либо в белом списке `publicRoot`, либо в `exclude`.

## Соглашения по контенту

До работы над учебным содержанием читай `LINGUIST.md`: роль лингвиста-аудитора, фактчекинг, формат аудита.

- Язык объяснений - русский, с опорой на русский и белорусский.
- Никаких комментариев в коде.
- **Никаких длинных тире (U+2014) нигде**, включая `.md` и сообщения коммитов: вместо него ` - `, запятая, двоеточие или скобки. Плейсхолдер «формы нет» в ячейке - голый `-` (с ним сравнивают компараторы в `app.js`). Неразрывный пробел U+00A0 тоже запрещён, короткое тире U+2013 разрешено. Проверяет `npm run lint`.
- Данные в `data.js` - массивы кортежей; порядок колонок задаёт `render*()`.
- Классы разметки: `.pl` - польское слово, `.w` - форма в ячейке, `.g` - пример, `.lead` - вводный абзац, `.tip` - врезка, `.vt` - таблица с шапкой, `.scroll` - обёртка для прокрутки, `.panel` - карточка. Ячейки: `.dim`, `.sm`, `.flow` (разрешить перенос), `.nw`, `.none`, `.sub`, `.gap`. В инлайновом `style` запрещены `color`, `white-space`, `font-family` (проверяется).
- Польский термин раздела - строка `<p class="term">по-польски: <span class="pl">…</span></p>` сразу под `h2`/`h3`, а не в тексте заголовка. `afterLead()` в `build.mjs` перешагивает через `.term`.
- `h3` получают якоря `~slug` из текста (`linkHeadings`): `/verbs/#~управление`, в вариантах `/cases/#dop/pl/~slug`. **Переименование `h3` ломает внешние ссылки.**
- ID заданий выводятся из содержимого (`taskSlug()`, у ложных друзей - польское слово), не из позиции: иначе вставка строки сдвинет накопленную статистику. Заперто в `check-build.mjs`. Переименование текста задания меняет его ID.
