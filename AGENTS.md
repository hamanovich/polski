# Проект: polski

## Архитектура

- `data.js` и `app.js` - исходники содержания и рендеринга справочника.
- `index.template.html` - общий HTML-шаблон справочника.
- `scripts/build.mjs` генерирует `index.html`, страницы разделов, `search-index.js` и `fulltext.txt`.
- Не редактировать сгенерированные HTML-страницы вручную: менять исходники и запускать `npm run build`.
- `plan-40/index.html` - отдельная статическая страница личного плана.

## Стили

- Единственный CSS-файл проекта - `style.css`.
- Не создавать inline-CSS и локальные CSS-файлы для отдельных страниц.
- Стили, уникальные для плана, добавлять в `style.css` и ограничивать селектором `body.plan-page`.
- Перед созданием нового компонента сначала искать и переиспользовать существующие классы, токены и контейнеры:
  - `.wrap`
  - `.head-in`
  - `.panel`
  - `--w`
  - `--measure`
  - цветовые токены `--paper`, `--panel`, `--ink`, `--muted`, `--line`, `--end`, `--alt`
- Не переопределять ширину, горизонтальные отступы, шрифты или тему страницы, если это уже задано общим CSS.
- При переносе CSS переносить не только цвета и размеры, но и структурные свойства: `display`, `grid`, `flex`, `position`, отступы, границы и состояния.

## Проверка

- После изменения исходников справочника: `npm run build && npm run check`.
- Перед коммитом: `npm run verify` - сборка, проверки и `git diff` по сгенерированным файлам. То же самое гоняет CI.
- После визуальных изменений проверять страницу в браузере и сверять computed styles с существующими страницами.
- Не заявлять, что лейаут совпадает, пока не сверены `width`, `max-width`, `padding` и ключевые `display`-свойства.

## Правило изменений

- Не менять текст учебных материалов, если пользователь явно просит изменить только оформление.
- Не добавлять новые UI-элементы без прямой необходимости.
- Никогда не писать комментарии в коде.
- **Без длинного тире:** Никогда не использовать символ длинного тире (U+2014) ни в одном файле: ни в `.js`, ни в `.html`, ни в `.css`, ни в `.md` - ни в данных, ни в разметке, ни в сообщениях коммитов. Вместо него использовать дефис (`-`), запятую, двоеточие или скобки. Правило проверяется автоматически: `npm run lint`.
